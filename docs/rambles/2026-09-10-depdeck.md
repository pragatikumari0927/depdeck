# Depdeck — design grill brief

2026-09-10. Trail for the grilling session. Not a spec; decisions below are locked unless superseded.

## Mission

A Go CLI that turns project dependencies into Pokémon-style trading cards, and an MCP server so agents can query the same dependency health through one shared pipeline.

## Locked

- Product is **two faces, same core**: CLI and MCP are thin adapters over one pipeline.
- Brief lives here (`docs/rambles/2026-09-10-depdeck.md`), not `CLAUDE.md` (repo uses `AGENTS.md`), not conversation-only.
- Grill one question at a time; do not implement Go/MCP/HTML until shared understanding is confirmed.
- Domain layout is single-context (`CONTEXT.md` + `docs/adr/` at repo root).

## Q1 — Product surface (locked)

**Decision:** One pipeline, two thin adapters.

- Pipeline: parse → fetch → stats → flavor → list of Dependencies
- CLI adapter: pipeline, then HTML + human output
- MCP adapter: pipeline, then JSON

**ADR-worthy consequences (see `docs/adr/0001-two-faces-same-core.md`):**

1. Shared contract is the Dependency type: CLI `--json` and MCP tool responses are the same struct, one schema, one version number.
2. Exit codes are CLI-only. Pipeline returns `error`; each adapter translates (MCP: structured tool error).
3. Pipeline is a library: no stdout, no flag parse, no process exit.
4. `--flavor` default is `rule` on both faces. MCP must not silently call a local model. Same flag semantics, including `none`.

**Why:** MCP has no `deck.html`. CLI `--json` is already most of the MCP shape. Wrapping the CLI in MCP shells out and drifts. CLI-only leaves agents with no forced machine-readable path.

## Q2 — What belongs on the Deck (locked)

**Decision:** Directs only. `dependencies` and `devDependencies` on the Deck, tagged. `optionalDependencies` included and tagged. `peerDependencies` and `bundledDependencies` skipped. Lockfile pins the resolved version; it never expands the Deck.

**Contract fields:** `version` is always the declared range/exact from `package.json`; `resolved_version` is from the lockfile and omitted when absent (Option A).

**No-lockfile fetch (v1):** use registry `dist-tags.latest`; if that fails the range, fall back to the highest matching non-prerelease. No extra semver library in v1.

**Non-goal:** transitives. Supply-chain tools (`npm audit`, Socket, Snyk) own that; the roster metaphor is what you chose.

See `docs/adr/0002-directs-only-deck.md`.

## Q3 — Degraded Cards and fetch (locked)

**Decision:** Keep the Card; attach `errors[]` (`source`, `kind`, `detail`). Bound concurrency at 8 **per Source**, wrapping **network only** (cache hits free). v1 Source is npm; GitHub reserved.

**Degraded Card:** Rarity omitted (not Common). Stars/issues/age/chaos omitted. Rule Flavor still runs from `name`; AI Flavor skipped.

**CLI `check`:** fetch errors do not fail the run. Exit 3 (network) only if *every* fetch fails.

**MCP:** `get_card` on a 404 is a successful tool result with `errors`; MCP-level errors only for bad args or crashes.

**Registry URL:** reserved config; v1 hardcodes `registry.npmjs.org`.

See `docs/adr/0003-degraded-cards-and-fetch.md`.

## Q4 — Cache (locked)

On-disk HTTP cache in `os.UserCacheDir()/depdeck/` (Windows `%LocalAppData%\depdeck\`). Key `sha256(source + ":" + name + ":" + ttl_class)`, one file per package, JSON `{etag, status, fetched_at, body}`.

TTL: 200+body 24h; 304 refreshes 24h; 404 1h. Do not cache 429/5xx/timeout/network.

ETag on 200; expired entry sends If-None-Match; 304 refreshes `fetched_at`; 200 replaces body.

`--no-cache` skips reads and writes. Tests: `--no-cache` + fixture server, never live npm. `depdeck check` in CI **reads** cache (does not bypass). No TTL-0. Cache is npm responses by name, not per-project; no invalidate on `package.json` change; no `--refresh` for that.

See `docs/adr/0004-on-disk-http-cache.md`.

**Field name:** `version` is always declared (ADR-0002). Clash resolved in Q5.

## Q5 — Flavor v1 (locked)

`rule` and `none` only. `--flavor=ai` errors (CLI exit 2; MCP structured error), message points at v1.1. No silent fallback.

Rule engine: `len(errors) > 0` → `rule_name_only` (name hash); else `rule_full` (name + stats). Zero stars is not degraded. Same struct → same Flavor; npm down vs up may differ — do not force name-only for consistency.

Contract: `flavor_source` = `rule_full` | `rule_name_only`.

See `docs/adr/0005-v1-flavor-rule-or-none.md`.

## Q6 — HTML (locked)

One self-contained `deck.html` next to `package.json` (not CWD). `--out -` → stdout. Byte-identical HTML (no `generated_at`). `html/template` only; no `template.HTML`/`JS` on npm strings; filter JS is static. `--json` skips HTML. No `--both`. Size budget <150 KB / 47 Cards. No `serve`.

See `docs/adr/0006-self-contained-deck-html.md`.

## Q7 — MCP tools (locked)

Three tools: `list_deck(path, tag?, flavor?)`, `get_card(name, flavor?)` (npm only, no path), `check_deck(path)`. Envelope `{schema_version, tool, data}`. Flavor enum `rule`|`none`. `check_deck` returns `pass`, `flagged`, `reason`, `policy`. `isError` only for tool failure. Agent-facing one-line descriptions.

See `docs/adr/0007-mcp-three-tools.md`.

## Q8 — JSON envelope (locked)

Same envelope for CLI `--json` and MCP: `schema_version`, `generated_at`, `generated_by` (`depdeck x.y.z` — included), `tool`, `data`. `tool` stays Face-specific (`scan`/`check` vs `list_deck`/`check_deck`/`get_card`). HTML byte-identical; JSON is not. `data` shapes documented in ADR-0008. Consumers check schema major only. jq tax accepted; README recipes later.

See `docs/adr/0008-json-envelope.md`.
